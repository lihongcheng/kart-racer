# 第四阶段：最佳幽灵车、分段计时与在线试玩

范围：用户已确认交付前三项并开始开发。承接双赛道、Classic 赛车和现有计时成绩；实操训练、AI 超车、联网、道具赛和触控另行规划。

## 计时与回放

- 幽灵车对应每条赛道的**最佳三圈总成绩**，仅出现在计时模式，不参与碰撞、排名、计圈和音效。设置提供持久化显示开关，关闭显示不停止记录。
- 每圈三个计时段，对应现有第 8、16、24 个有序检查点，三圈共九段。以倒计时结束后的现有比赛计时为基准，第一段包含起跑线前的短距离；复位罚时计入当前段。
- 每次通过分段点显示相对开赛时个人最佳同一段的用时差与累计差；结算展示九段对比，以及进步最大、损失最多的路段。地图标记 S1/S2/终点；无基准时正常记录，不显示虚构差值。
- 比赛开始时冻结本场对比基准；本场刷新纪录后仍用开赛前的最佳进行结算比较，下一场再加载新最佳。
- 在固定物理时间步采样姿态（建议 10 Hz），渲染时依据比赛时间插值位置、最短方向角、车轮转向与加速状态，独立于渲染帧率；不通过重新模拟历史输入来回放。
- 暂停保持幽灵车姿态，继续不追赶墙钟时间；重赛从零开始。复位在回放中保留罚时停留与瞬移边界，禁止跨越瞬移插值穿过赛道。
- 回放使用压缩数值元组，包含时间、位置、高度、朝向、转向、速度、状态和跳变标记。限制最多 15 分钟、约 10,000 个样本；超出上限仍正常保存成绩与分段，但不保存不完整回放，并向用户提示。

## 保存与兼容

- 延续 `coastline.records.v2` 的历史与最佳成绩。新增独立版本化计时挑战存储，按赛道保存最佳场次的完整九段及可选回放。
- 只有刷新该赛道计时最佳总成绩时替换基准，较慢比赛不能覆盖。读取时核对赛道、布局/驾驶版本及最佳总时间，不让失效或错配回放冒充个人最佳。
- 旧存档没有历史轨迹，保持原成绩；提示刷新最佳后记录幽灵车，不生成替代跑法。
- 解析校验时间顺序、有限数值、样本上限、完整分段、赛道和版本；损坏回放不能阻止开赛。保存失败时保留当前页面可用状态并显示提示，不丢失已有成绩。
- 成绩引用同步更新，继续支持单次自动化调用内多场完赛，避免 React 批处理或旧闭包覆盖。

## 界面与资源

- 计时菜单展示最佳幽灵车状态和开关；HUD 显示本段、最近分段用时与相对差值；结算增加紧凑九段对比。兼顾 1280×720 和 1440×900。
- 幽灵车复用 Classic 简化网格，使用半透明统一材质、不投影、不产生粒子；资源随场景销毁，重赛复用。
- 所有发布模型、清单和下载链接使用 Vite base 路径，支持仓库子路径 `/kart-racer/` 和根路径部署。
- 静态生产站点直接加载发布清单，不轮询本地 `/api`；开发环境保留资产服务功能。公开试玩界面隐藏本地生成工作台。

## 验收

- 纯函数：30/60/120 FPS 回放取样一致；角度跨 ±π、暂停/重赛、复位罚时与跳变、边界时间、容量/异常输入、分段总和与累计差、赛道/版本隔离、旧纪录兼容、较慢成绩不覆盖。
- 浏览器：两赛道首场生成、第二场幽灵及分段对比；开关/刷新持久化、竞速模式无幽灵、暂停冻结、重赛归零；旧个人最佳无回放、存储失败和长局降级。
- 保留现有 39 项测试和 9 组浏览器回归；真实三圈比赛确认九段总和等于完赛时间且 ghost 不影响规则。
- 生产子路径：新浏览器直接加载两赛道、键盘驾驶、暂停/重赛、四件 GLB/工坊下载；无根路径资产请求或本地 API 轮询，无开发调试接口。
- 1080p 计时赛含可见幽灵的实时性能样本与截图；在线部署可用后再进行公开地址验收。只报告实际测量和已完成步骤。
