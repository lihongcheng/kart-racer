# 第二阶段交付：驾驶反馈与渲染打磨

日期：2026-10-01。入口：[开发版](http://localhost:5174) / [生产预览](http://127.0.0.1:4176)。本阶段沿用海风环线、Classic 赛车与现有单机玩法。

## 已交付

- **驾驶**：在固定 60 Hz 物理步中渐进转向，高速适度降低偏航响应，保持 A/← 左转、D/→ 右转。30/60/120 渲染 FPS 的物理轨迹仍一致。
- **漂移反馈**：有效漂移满 0.6 秒显示“小喷就绪 · 松开 SHIFT”，伴随火花；松开 Shift 后小喷持续 0.7 秒。短漂、单独松方向键、失速、驶出道路、碰撞都不会获得小喷。HUD 区分小喷和氮气。
- **镜头与暂停**：平滑处理朝向与注视点，小喷/氮气逐渐拓宽视野；关闭镜头效果后比赛固定 62°。暂停冻结车轮、尾焰、漂移烟雾和胎痕，继续比赛不会把清空按键误判成小喷操作。
- **特效复用**：96 个粒子槽、160 个胎痕槽，两组实例网格；持续漂移和重赛复用几何、材质及缓冲区，重赛清空可见实例。
- **场景绘制**：赛道中线及 Rodin 棕榈/岩石按 72 米空间格分批实例化，起点方格使用实例颜色，保留分区视锥剔除。
- **AI 远景模型**：距相机超过 35 米切为简化模型，回到 31 米以内恢复精细模型。保留大头盔、车头、尾翼、四轮和配色，轮组动画在两个版本中同步。玩家与车库始终使用精细版本。

精细/简化程序模型的静态三角形分别为 **37,134 / 17,414**，减少 **53.1%**，不含尾焰。工坊下载的精细 GLB 经 glTF Transform 优化，为 30,438 个三角形；两种统计口径不同。

## 同条件静态性能对比

Apple M5 Pro / 48 GiB / macOS，Chrome 149.0.7827.54 无头浏览器，1920×1080、deviceScaleFactor=1。同一脚本、每场景 90 帧，菜单航拍与暂停起跑线分别采样。两档画质的绘制统计基本一致。

| 精致画质场景 | 优化前绘制调用 | 优化后绘制调用 | 变化 | 渲染三角形：前 → 后 |
| --- | ---: | ---: | ---: | ---: |
| 菜单航拍 | 441 | 268 | -39.2% | 442,832 → 344,232（-22.3%） |
| 起跑线 | 223 | 131 | -41.3% | 251,258 → 238,804（-5.0%） |

这些场景前后均约 121 FPS，空白页基线也约 121 FPS，因此改善主要体现在绘制开销，不能据此声称帧率翻倍。分区实例化会多提交同一格内部分屏外模型，实际三角形变化取决于镜头和 AI 距离。

菜单 GPU 已上传几何计数从 375 降至 227；进入近景后为 372，因为精细与简化模型会保留已上传资源。这里是几何对象数量，不是显存字节数；不据此宣称整体内存同比降低。

原始数据：[优化前](performance-phase2-before.json) / [优化后](performance-phase2-after.json)。复现：`node scripts/benchmark.mjs <label>`。

## 实际比赛性能

通过 `node scripts/benchmark-race.mjs` 进行实时渲染采样：普通难度、六辆赛车、镜头效果开启，两档画质各 40 秒，从第一圈行驶至第二圈。采样期间按真实时间推进物理，不使用加速仿真。

| 画质 | 平均 FPS | P95 帧间隔 | 大于 33.34 ms 的帧 |
| --- | ---: | ---: | ---: |
| 精致 | 120.01 | 9.1 ms | 0 / 4,801 |
| 流畅 | 120.01 | 9.1 ms | 0 / 4,801 |
| 同浏览器空白页基线 | 120.22 | — | — |

本机无头浏览器样本达到 60 FPS 数值目标，不代表其他机器或显示环境均能保持该帧率。采样无游戏运行或 WebGL 错误；浏览器自动请求的 `favicon.ico` 返回 404，已单独记录为资源提示。

完整帧率、P95 帧间隔、绘制统计、LOD/漂移帧数及异常记录见 [实际比赛采样](performance-phase2-race.json)。首版曾记录约 30 FPS 且空白页同为 30 FPS；该历史环境与本轮刷新率不同，不做跨环境性能倍数比较。
