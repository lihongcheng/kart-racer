# 修复 CI 驾驶实操断言超时

日期：2026-10-02。

## 原因

GitHub Actions 在第一课等待 `.training-card li.done` 数量变为 1 时，5 秒后失败；错误现场速度为 42 km/h，低于课目要求的 54 km/h，页面没有 JS 错误或错误路径请求。

`scripts/validate-production.mjs` 由 `node` 直接运行，不加载 Playwright 测试运行器配置。`page.setDefaultTimeout(60_000)` 仅设置页面操作/等待的超时，不会改变 `expect(locator)` 默认的 5 秒期限。

引擎每个渲染帧最多推进 0.1 秒模拟时间，以防止卡顿后产生大幅跳跃。在无物理 GPU 的 SwiftShader 环境中，如果渲染帧率很低，完成约一秒的加速模拟可能需要超过五秒真实时间。本机较快渲染不能证明云端始终可以在五秒内完成。

## 修改

- 使用 `playwrightExpect.configure` 显式设置断言默认超时：CI 60 秒，本机 10 秒。等待条件一旦达成即结束，不固定等待一分钟。
- 保留真实键盘输入、54 km/h 达标判定、课目计数、刷新恢复和存档隔离验证。
- 成功报告记录实际断言超时及第一课加速的真实耗时。
- 失败报告增加游戏用时、页面可见性、已完成课目、当前操作提示与进度，区分慢渲染、暂停、碰撞或离开道路。

## 受控复现

使用同一生产构建、Chrome 149、1280×720 和 SwiftShader。仅在复制的验收脚本中为第一课期间的动画帧增加 600 ms 调度延迟；不修改车辆物理、输入或完成条件。该延迟用于模拟低帧率，不代表对 GitHub 运行器实际帧率的测量。

| 用例 | 结果 |
| --- | --- |
| 原版脚本，默认断言 5 秒 | 复现失败：期望 1、实际 0，现场速度 46 km/h，无页面错误 |
| 修复版，同样的动画帧延迟 | 第一课耗时 6,301 ms，完整静态验收通过 |
| `npm test` | 67/67 通过 |

动画帧延迟仅存在于本机 `test-results/` 下的临时复现副本，没有加入正式脚本或游戏包。此前的 itch.io 发布准备保留在工作区，本次修复提交仅包含 CI 等待与诊断变更。
