# 第三阶段：双赛道与赛事奖牌

状态：2026-10-01 已完成实现与自动化验收，详见 [第三阶段交付记录](phase3-validation.md)。

承接第二阶段体验打磨。目标是让玩家可以选择不同赛道，并有持续挑战的成绩目标，继续保持 PC 键盘、Classic 赛车、快速竞速与三圈计时的完整闭环。

## 交付范围

1. 保留“海风环线”，新增“落日峡谷”：独立路线、连续弯与缓坡、砂岩台地、暖色夕阳环境。复用已有 Rodin 棕榈/岩石及 Classic 赛车，地形与装饰采用程序几何，不需要新的付费生成。
2. 主菜单赛道选择展示两张路线图、长度、特点与目标；选中赛道同步驱动 3D 环境、出生点、护栏、AI、检查点、复位点、HUD、迷你地图和结算。
3. 竞速奖牌按完赛名次：第一名金牌、第二/三名银牌、其他完赛铜牌。计时按每条赛道的三圈总用时门槛评定金/银/铜；超出铜牌门槛显示完成及下一目标。
4. 纪录按赛道和模式区分，结算展示奖牌与个人最佳提示；菜单展示当前赛道/模式的最佳单圈和已获奖牌。保留最近 30 场历史，最佳成绩与奖牌进度长期保存。
5. 旧版没有赛道字段的本地成绩归入海风环线；旧设置默认海风环线。切换、刷新、暂停和连续重赛保持一致。

## 技术实现

- `track.ts` 提供不可变赛道对象与目录：`id/name/subtitle/theme/width/length/points/at/project/minimapPath/mapPosition/medals`。数学工具与默认海风环线兼容导出保持现有测试可用，禁止使用全局可变“当前赛道”。
- `KartGame` 从已校验的 `settings.trackId` 获取赛道对象，所有位置和碰撞判断使用该对象；Snapshot 含赛道 ID。保持现有 `debug.start/advance` 接口，用真实物理做双赛道回归。
- React 在赛道 ID 变化时清理并重建游戏实例（场景、物理世界、监听器、RAF）；复用已有 Rapier 初始化 Promise。忽略/释放旧实例晚到的资产结果，开发接口不能引用已销毁实例。设置/配色变更仍原地更新。
- 环境构建接收赛道对象；道路由对应样条生成。峡谷使用不同地面、天空、灯光与岩柱，装饰不得占用道路；保留实例化和 AI LOD。
- 新增独立成绩模块，纯函数负责有效数据解析、迁移、奖牌、最佳成绩与历史更新。使用版本化成绩对象（历史 + 各赛道/模式最佳），写入新 localStorage 键，读取时优先新版，无新版时迁移旧 `coastline.records`，不删除旧数据。
- 完赛更新必须支持一次自动化调用内连续多次完赛，避免 React 批处理导致旧闭包覆盖成绩。用同步 ref 保存当前成绩状态并更新 React/存储。

## 验收

- 两条赛道分别验证中心线投影、起点/地图、道路不自交、完整有序检查点。
- 覆盖奖牌边界、不同赛道/模式隔离、旧成绩迁移、异常存档、最近 30 场截断后最佳仍保留。
- 保留原 27 项单元/规则/服务测试及 5 组浏览器验收；扩展双赛道、两档 AI 连续完赛，五名 AI 独立完赛、计时、切换后复位与存档。
- 实际键盘验证峡谷加速/转向，观察新场景、选赛和奖牌截图；反复切换时仅一个主 canvas 且无页面异常。
- TypeScript + 生产构建、静态生产版双赛道流程、1080p 新赛道实际比赛性能采样。FPS 只报告测量结果。

## 边界

幽灵车、触控、更多车型、道具赛、联网不包含在本阶段；本轮不重做已交付的赛车外观。奖牌时间门槛为首轮调参值，自动驾驶验收不能代替人工手感与难度试玩。
